# 🛒 Интернет-магазин — PostgreSQL

## 📌 Описание проекта

Данный проект представляет собой базу данных интернет-магазина, разработанную на **PostgreSQL**.

База данных позволяет хранить информацию о:

* пользователях;
* товарах;
* заказах;
* товарах внутри заказов;
* ценах и остатках на складе.

Также реализованы функции, триггеры, хранимая процедура, представление, индексы, управление доступом, RLS и резервное копирование.

---

# 🗂 Структура базы данных

Проект содержит следующие основные таблицы:

```text
users
  │
  └── orders
        │
        └── order_items
                │
                └── products
```

### Таблица `users`

Хранит информацию о пользователях интернет-магазина.

| Поле         | Тип          | Описание                 |
| ------------ | ------------ | ------------------------ |
| `id`         | SERIAL       | Уникальный идентификатор |
| `email`      | VARCHAR(255) | Электронная почта        |
| `имя`        | VARCHAR(100) | Имя пользователя         |
| `created_at` | TIMESTAMP    | Дата регистрации         |

### Таблица `products`

Хранит информацию о товарах.

| Поле       | Тип           | Описание                    |
| ---------- | ------------- | --------------------------- |
| `id`       | SERIAL        | ID товара                   |
| `название` | VARCHAR(200)  | Название товара             |
| `цена`     | NUMERIC(10,2) | Цена                        |
| `остаток`  | INT           | Количество товара на складе |

### Таблица `orders`

Хранит информацию о заказах.

| Поле         | Тип         | Описание      |
| ------------ | ----------- | ------------- |
| `id`         | SERIAL      | ID заказа     |
| `user_id`    | INT         | Пользователь  |
| `статус`     | VARCHAR(20) | Статус заказа |
| `created_at` | TIMESTAMP   | Дата создания |

### Таблица `order_items`

Связывает заказы с товарами.

| Поле         | Тип | Описание          |
| ------------ | --- | ----------------- |
| `order_id`   | INT | ID заказа         |
| `product_id` | INT | ID товара         |
| `количество` | INT | Количество товара |

Первичный ключ:

```sql
PRIMARY KEY (order_id, product_id)
```

# 🧮 Функция `order_total`

Функция:

```sql
order_total(p_order_id)
```

вычисляет общую стоимость заказа.

Формула:

```text
Сумма = количество × цена
```

Для каждого товара из заказа стоимость рассчитывается отдельно, после чего значения складываются.

Пример:

```sql
SELECT order_total(1);
```

Результат:

```text
order_total
------------
82000.00
```

# 📦 Проверка склада

Для контроля количества товаров используется функция:

```sql
check_stock()
```

Она вызывается автоматически триггером:

```sql
trg_check_stock
```

Перед добавлением товара в заказ проверяется его остаток.

Если пользователь пытается купить больше товара, чем есть на складе, PostgreSQL выдаёт ошибку:

```text
Недостаточно товара на складе
```

Если товар доступен, его остаток автоматически уменьшается.

---

# 🔄 Триггер

Используется триггер:

```sql
CREATE TRIGGER trg_check_stock
BEFORE INSERT
ON order_items
FOR EACH ROW
EXECUTE FUNCTION check_stock();
```

Алгоритм:

```text
Добавление товара в заказ
        ↓
Проверка товара
        ↓
Проверка остатка
        ↓
Достаточно?
   ┌────┴────┐
  ДА         НЕТ
   ↓          ↓
Списать     Ошибка
товар
   ↓
Добавить заказ
```

# 🧾 Хранимая процедура `create_order`

Для создания заказа используется:

```sql
CALL create_order(...)
```

Процедура:

1. проверяет существование пользователя;
2. создаёт новый заказ;
3. добавляет товары;
4. запускает проверку склада;
5. уменьшает остаток товаров;
6. выводит номер созданного заказа.

Пример:

```sql
CALL create_order(
    1,
    ARRAY[
        ROW(1, 1)::order_item_type,
        ROW(6, 2)::order_item_type
    ]
);
```

В результате создаётся заказ пользователя с ID `1`.

# 📊 Типовые запросы

## Заказы пользователя

```sql
SELECT
    o.id,
    o.статус,
    order_total(o.id) AS сумма
FROM orders o
WHERE o.user_id = 1
ORDER BY o.created_at DESC;
```

---

## Товары с малым остатком

```sql
SELECT
    id,
    название,
    цена,
    остаток
FROM products
WHERE остаток < 10
ORDER BY остаток ASC;
```

---

## Продажи за текущий месяц

```sql
SELECT
    p.название,
    SUM(oi.количество) AS продано
FROM order_items oi
JOIN products p
    ON p.id = oi.product_id
JOIN orders o
    ON o.id = oi.order_id
WHERE o.created_at >= DATE_TRUNC('month', NOW())
GROUP BY
    p.id,
    p.название
ORDER BY
    продано DESC;
```

# 🔐 Управление доступом

В проекте предусмотрены две роли:

```text
app_user
readonly
```

`app_user` предназначена для работы приложения.

Предполагаемые права:

```text
SELECT
INSERT
UPDATE
```

Роль `readonly` предназначена для пользователей, которым требуется только чтение данных.

```text
SELECT
```

> Создание ролей требует прав `CREATEROLE`. Поэтому в учебном `commands.sql` команды `CREATE ROLE` могут быть закомментированы, если PostgreSQL запущен под обычным пользователем.

# 🛡 RLS

Для таблицы `orders` используется:

```text
Row Level Security
```

RLS позволяет ограничить доступ пользователя только его собственными заказами.

Включение:

```sql
ALTER TABLE orders
ENABLE ROW LEVEL SECURITY;
```

Политика:

```sql
CREATE POLICY own_orders
ON orders
USING (
    user_id = current_user_id()
);
```

Идентификатор текущего пользователя передаётся через параметр:

```sql
SET app.current_user_id = '1';
```

После этого пользователь может получать только свои заказы.

# 💾 Резервное копирование

Для создания резервной копии используется:

```bash
pg_dump -Fc mydb > backup.dump
```

Для восстановления:

```bash
pg_restore -d mydb backup.dump
```

Где:

```text
mydb
```

— название базы данных.
